Layer 2: End-to-End (Ship Gate)

Does the whole system produce correct incident timelines?

  • Detection recall ≥ 0.90 (P0) / 0.80 (P1)
  • Precision ≥ 0.75 (P0) / 0.80 (P1)
  • Classification accuracy ≥ 0.85
  • Temporal IoU mean ≥ 0.60
  • FP rate on negatives ≤ 0.05
  • All per venue_type, lower CI bound

Layer 1: Component Diagnostics

Which stage is the bottleneck?

  • Gemini per-chunk: isolated recall/precision
  • Merge: completeness, no duplication
  • D-FINE: mAP@0.5 ≥ 0.85
  • InsightFace: TAR@FAR=0.01 ≥ 0.90
  • Summary: P0 recall in review group = 1.0
  • Semantic search: Recall@10 ≥ 0.85, MRR@10 ≥ 0.60

The 1–5 unified judge is withdrawn. Overlap checks are deterministic. Incident judgments stay with a named reviewer. A summary check may use an LLM only as a shadow until held-out acceptance exists. No kappa cutoff is a gate.

Error Analysis Flow

L2 drop beyond trigger_threshold?
├─ NO → Log. No action.
└─ YES → Pull traces for degraded venue_type
    ├─ High FP → Check Gemini hallucination (Stage 1)
    ├─ High FN → Check boundary recall (Stage 2) + chunk recall (Stage 1)
    ├─ Classification drop → Check template version / behaviour defs
    ├─ Temporal drop → Check merge logic (Stage 2) + chunk timestamps
    └─ Search quality drop → Stage 7 on pinned corpus; if it passes → caption quality (Stage 1)

Automated: this tree is encoded in the harness regression router (doc 6D) — a confirmed drop auto-enqueues the mapped Stage-N diagnostic run and writes results to Langfuse before human error analysis begins. The diagnosis and fix remain human work.

Eval Harness & Automation

Mode 1 — Golden Layer 2
RELEASE GATE · ground truth
Runs golden-v1 as a Langfuse Dataset Run through the real pipeline; unified judge runs in the harness; metrics + CIs computed deterministically; gates on lower CI bounds; exits 0/1 for CI. N=3 named runs for consistency.
Mode 2 — Layer 1 Component
DIAGNOSTICS · ground truth
4 automation groups: merge/combine fixtures (free, every PR) · Gemini component sets (Stage 1/4) · CV metrics (D-FINE, InsightFace) · pinned-corpus retrieval (Stage 7). Auto-routed by changed paths + Layer 2 regressions.
Mode 3 — Post-Prod Judge Audit
MONITORING · no ground truth
Judge over sampled production traces (100% of user-flagged — never sampled away). Emits proxy scores only (judge_pass_fail, suspected miss/FP) — never eval_* names, never a gate. Drift alert → targeted Mode 1 run.

Harness = computes metrics & enforces gates (exit 0/1) · Langfuse = stores & visualizes evidence · CI = blocks merge/release

Automation boundary (doc 6I): automated — execution, routing, alerting. Permanently human — ground-truth labeling, judge calibration, adversarial case crafting, root-cause diagnosis, ship/no-ship sign-off, dataset composition decisions.
