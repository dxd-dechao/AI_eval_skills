# SmartCampus — Codebase Architecture Overview

## What is SmartCampus?

SmartCampus is a **multi-venue school video analytics platform**. You upload CCTV/classroom video from any venue (classroom, exam hall, canteen, library, corridor, playground) and **Gemini** analyzes it, producing:

- **Behaviour timelines** — per-clip incident detection with timestamps
- **Incident cases** — synthesized case reports from grouped incidents
- **ROI analytics** — person-detection line crossings (via D-FINE GPU sidecar)
- **Face indexing** — face embedding & recognition (via InsightFace GPU sidecar)
- **Semantic clip search** — natural-language video search (via AWS S3 Vectors)

## High-Level Architecture

```
Browser
  │  /smartcampus/*              /api/* , /auth/*
  ▼                                ▼
Frontend (Next.js 16, CSR)      Slim BFF (FastAPI)
 apps/web  :3008                 services/bff  :8000
                                   │  Cognito cookie auth + reverse proxy
                                   ▼  /api/smartcampus/* ──▶ Backend (FastAPI)
                                                              services/api  :8003
                                                                │
                                     ┌─────────────────────────┼──────────────┐
                                     ▼           ▼              ▼              ▼
                                Firestore     GCS          Cloud Tasks     GPU sidecars
                              labs-smartcampus prototype_   smartcampus-   dfine / face
                                              web_apps      pipeline       + S3 Vectors
```

> [!IMPORTANT]
> The frontend talks **only** to the BFF. The BFF authenticates via Cognito httpOnly cookies (supporting TechPass federated login with a SmartCampus admin-only login gate) and reverse-proxies `/api/smartcampus/*` to the backend.

### Design Philosophy
- **Serverless-first** — all services are Cloud Run, scale-to-zero
- **CSR-only frontend** — Node server is for routing only, all data fetching is client-side via TanStack Query
- **No persistent connections** — no WebSockets/SSE; long-running analysis is async via Cloud Tasks, polled by the frontend
- **Managed services only** — Firestore, GCS, Cloud Tasks. No self-managed infra

## Key Subsystems

### 1. Venue Template System (core abstraction)
Instead of hardcoded behaviours, each analysis is driven by a **venue template** that defines:
- Behaviour categories (with on/off toggles)
- System/user prompt templates (with `{behavior_categories}` / `{venue_orientation}` placeholders)
- Camera orientation config
- Schema type for Gemini structured output

6 built-in defaults: `classroom`, `exam_hall`, `canteen`, `library`, `corridor`, `playground`. Users can add custom ones.

### 2. Analysis Pipeline (async, Cloud Tasks)
4 OIDC-protected internal steps:
1. **start** — chunk video + enqueue
2. **process-batch** — Gemini analysis per chunk
3. **merge** — stitch incidents across chunk boundaries
4. **combine** — multi-duration final merge

Modes: `whole`, `chunked`, `multi_duration`
